# Local BIND DNS Management for Docker Containers

This module provides automatic DNS record management for Docker containers using a local BIND DNS server. The system is designed to run in containers with crontab scheduling on the host.

## Features

- Automatically discover running Docker containers
- Get container IP addresses from Docker networks
- Support for container labeling to control DNS management
- Local BIND zone file management
- A record creation and cleanup
- Containerized architecture with volume mounts
- CLI interface for manual operations

## Architecture

```
Host System
├── BIND Container (bind9)
│   ├── Zone files mounted from host
│   └── DNS server on port 53
├── Infradmin Container
│   ├── Docker socket mounted
│   ├── Zone files mounted (same as BIND)
│   └── DNS update scripts
└── Crontab (on host)
    └── Executes DNS updates in infradmin container
```

## Configuration

### DNS Settings in config.yaml

```yaml
dns:
  domain: "local.dev"  # Your local domain name
  subdomain_prefix: "container"  # Prefix for container subdomains
  ttl: 300  # DNS record TTL in seconds
  
  # BIND configuration (container-based)
  bind:
    zone_file_path: "/etc/bind/zones"  # Path inside BIND container
    zone_file_name: "db.local.dev"  # Zone file name
    bind_container_name: "bind9"  # Name of the BIND container
    reload_command: "rndc reload"  # Command to reload BIND configuration
```

### Container Labels

To enable DNS management for specific containers, add these labels:

```yaml
labels:
  # Enable DNS management for this container
  - "infradmin.dns.enable=true"
  # Custom subdomain (optional, defaults to container name)
  - "infradmin.dns.subdomain=myapp"
```

## Setup Instructions

### 1. Prepare Directory Structure

```bash
mkdir -p ./bind/zones
mkdir -p ./bind
mkdir -p ./data
```

### 2. Configure BIND

Copy the example configuration files:
- `conf/bind/named.conf.local` → `./bind/named.conf.local`
- `conf/bind/db.local.dev` → `./bind/zones/db.local.dev`

### 3. Deploy with Docker Compose

Use the example `docker-compose-dns-example.yml` as a starting point:

```bash
docker-compose -f conf/docker/docker-compose-dns-example.yml up -d
```

### 4. Set up Crontab on Host

Add to your host crontab (crontab -e):

```bash
# Update DNS records every 2 minutes
*/2 * * * * /usr/bin/docker exec infradmin python /usr/src/app/infradmin/scripts/updateDNS.py --sync

# Cleanup old DNS records every hour
0 * * * * /usr/bin/docker exec infradmin python /usr/src/app/infradmin/scripts/updateDNS.py --cleanup
```

## Usage

### Command Line Interface

```bash
# List all running containers and their IPs
docker exec infradmin python scripts/updateDNS.py --list

# List containers with DNS labels
docker exec infradmin python scripts/updateDNS.py --list-dns

# Sync DNS records for labeled containers only
docker exec infradmin python scripts/updateDNS.py --sync

# Sync DNS records for all running containers
docker exec infradmin python scripts/updateDNS.py --sync-all

# Clean up DNS records for stopped containers
docker exec infradmin python scripts/updateDNS.py --cleanup
```

### Programmatic Usage

```python
from scripts.updateDNS import DNSUpdater

# Initialize with default config
updater = DNSUpdater()

# Get all container IPs
container_ips = updater.get_all_container_ips()

# Get containers with DNS labels
dns_containers = updater.filter_containers_with_dns_labels()

# Sync DNS records
success = updater.sync_dns_records(force_all=False)

# Cleanup old records
success = updater.cleanup_dns_records()
```

## DNS Record Format

Records are created as: `{subdomain_prefix}-{container_name}.{domain}`

Examples:
- `container-webapp.local.dev`
- `container-api.local.dev`
- `container-database.local.dev`

## Volume Mounts

The system requires shared volume mounts:

```yaml
# BIND container
volumes:
  - ./bind/zones:/etc/bind/zones:rw

# Infradmin container
volumes:
  - /var/run/docker.sock:/var/run/docker.sock:ro
  - ./bind/zones:/etc/bind/zones:rw
```

## Container Network Discovery

The script automatically discovers container IPs from:
- Docker bridge networks
- Custom Docker networks
- First available network interface per container

## Zone File Management

### Automatic Generation

The system generates complete zone files with:
- Dynamic serial numbers (timestamp-based)
- SOA records with proper configuration
- NS records for the domain
- A records for each container

### Example Generated Zone File

```dns
; Zone file for local.dev - Auto-generated by infradmin
; Generated on: 2025-07-18 14:30:15
$TTL 300
@       IN  SOA ns1.local.dev. admin.local.dev. (
                1721311815  ; Serial
                3600        ; Refresh
                1800        ; Retry
                604800      ; Expire
                300         ; Minimum TTL
                )

        IN  NS  ns1.local.dev.
        IN  NS  ns2.local.dev.

; Static records
ns1     IN  A   127.0.0.1
ns2     IN  A   127.0.0.1

; Container A records - Auto-generated
container-webapp               IN  A   172.18.0.3
container-api                  IN  A   172.18.0.4
container-database             IN  A   172.18.0.5

; End of auto-generated records
```

## Error Handling

- Invalid IP addresses are filtered out
- Missing containers are logged and skipped
- BIND container communication errors are handled gracefully
- Partial failures don't stop the entire sync process
- Zone file write failures are logged with detailed errors

## Troubleshooting

### Common Issues

1. **No containers found**: Check Docker socket mount and permissions
2. **BIND reload fails**: Verify BIND container is running and rndc is configured
3. **Zone file not updated**: Check volume mount permissions and paths
4. **DNS not resolving**: Verify BIND container port mapping and firewall

### Debug Commands

```bash
# Check container status
docker exec infradmin python scripts/updateDNS.py --list

# Test BIND container communication
docker exec infradmin python -c "
from common.containers import Docker
d = Docker()

# Test DNS resolution

```

### Log Monitoring

Monitor cron job execution:

```bash
tail -f /var/log/infradmin-dns.log

# Check cron execution
grep DNS /var/log/syslog
```

## Security Considerations

- Docker socket is mounted read-only
- BIND container runs with minimal privileges
- Zone files are writable only by infradmin container
- No external network access required for DNS updates
- RNDC key should be properly secured

## Integration with Infradmin

This DNS updater integrates seamlessly with infradmin:
- Uses `common.containers.Docker` for container management
- Uses `common.infradmin_logs` for consistent logging
- Follows infradmin label conventions
- Shares volume mounts with other infradmin components
